# Science Assistant — руководство MCP-сервера

## 1. Назначение и архитектура

Science Assistant получает научные каталоги и файлы без одноразовых сетевых скриптов. Сервер построен только на command registry `mcp-proxy-adapter`; пользовательских REST-контроллеров и параллельного API нет.

Пользователь вызывает Science Assistant через MCP Proxy. Для больших двоичных файлов используется собственный поток Base64-чанков внутри обычных `call_server`, поэтому клиенту не нужен прямой сетевой маршрут к контейнеру.

Основные группы команд:

- `info` — документация, версии и runtime-инвентарь;
- `astroquery_catalog`, `astroquery_object`, `astroquery_adql` — научные запросы;
- `download_file` — загрузка публичного HTTP/HTTPS/FTP-ресурса на сервер;
- `data_upload_*` — поток клиент → сервер через MCP Proxy;
- `data_download_*` — поток сервер → клиент через MCP Proxy;
- `data_package_part`, `data_package_wait`, `data_package_status` — независимые части и ожидающая атомарная сборка для агентных сред.

## 2. Версии

Версия сервера, Python-пакета, Docker image, Debian-пакета и пакета клиента должна совпадать. Единственный источник релизной версии — корневой `pyproject.toml`. Сборка синхронизирует клиентский `version.py` и прекращается при расхождении.

Клиент при подключении вызывает `info(include_markdown=false)` и по умолчанию отказывается продолжать при несовпадении версии.

## 3. Пагинация длинного вывода

`info` возвращает документацию стабильными блоками строк:

```json
{"page_size": 80, "block_position": 1, "include_markdown": true}
```

Ответ содержит:

```json
{
  "markdown": "текст текущей страницы",
  "pagination": {
    "paginated": true,
    "page_size": 80,
    "block_position": 1,
    "total_lines": 260,
    "total_blocks": 4,
    "has_more": true,
    "next_block_position": 2
  }
}
```

`block_position` начинается с 1. Страницы обходятся по возрастанию до `has_more=false`. Пакет `science-assistant-client` делает это автоматически. Двоичный вывод `data_download_chunk` уже пагинирован по байтовым offset и limit.

## 4. Каталоги, пути и пользователь

- процесс контейнера: `scasuser:scasgrp`;
- конфигурация: `/etc/science-assistant`;
- данные: `/var/science-assistant/data`;
- журналы: `/var/log/science-assistant`;
- mTLS: `/etc/science-assistant/mtls`.

Все прикладные пути относительны к `/var/science-assistant/data`. Абсолютные пути, пустые компоненты, `.` и `..` запрещены. Ответы содержат `relative_path` для последующих команд и `server_path` только для диагностики.

## 5. Форматы поисковых запросов

### 5.1 VizieR: `astroquery_catalog`

`catalog` — официальный идентификатор VizieR, например:

- `J/ApJ/714/25`;
- `J/ApJS/164/334`;
- `I/355/gaiadr3`.

`table` — полный ключ таблицы либо его однозначный суффикс: `J/ApJ/714/25/table1`, `table1`, `struct`.

`columns` — массив точных названий столбцов. `"*"` запрашивает стандартный набор. Специальные выражения VizieR, например `+_r`, допустимы только если сервис и таблица их поддерживают.

`constraints` — объект `имя_столбца: строка_ограничения`. Примеры:

```json
{"Gmag": "<12"}
{"z": "0.01..0.1"}
{"Class": "GALAXY"}
```

Имена и семантика ограничений определяются выбранной таблицей VizieR. `row_limit=-1` снимает клиентское ограничение astroquery; положительное значение ограничивает строки каждой таблицы.

### 5.2 SIMBAD, NED, VizieR, HEASARC, IRSA: `astroquery_object`

Есть два взаимозаменяемых способа задать позицию:

- `target`: имя, распознаваемое выбранным сервисом, например `M 31`, `NGC 1275`, `3C 273`;
- `ra_deg` и `dec_deg`: десятичные градусы ICRS, передаются только парой.

Диапазоны: `0 <= ra_deg < 360`, `-90 <= dec_deg <= 90`. `radius_arcmin > 0` включает поиск по конусу. Для HEASARC и IRSA поле `catalog` обязательно; для VizieR оно ограничивает поиск конкретным каталогом.

### 5.3 Gaia и TAP: `astroquery_adql`

`query` содержит полный ADQL-запрос. Поддерживаются `SELECT`, `TOP`, `WHERE`, `JOIN`, `ORDER BY`, агрегаты и геометрические функции, реализованные выбранным TAP-сервисом.

Gaia:

```sql
SELECT TOP 100 source_id, ra, dec, phot_g_mean_mag
FROM gaiadr3.gaia_source
WHERE phot_g_mean_mag < 12
ORDER BY phot_g_mean_mag ASC
```

Произвольный TAP задаётся `service="custom"` и `tap_url`. Во время разработки используйте `TOP`; фильтрацию и агрегацию выполняйте на стороне TAP.

### 5.4 NIST

У NIST нет единого универсального API для всех научных баз.

- Atomic Spectra Database (ASD) предоставляет официальный веб-интерфейс и CGI-параметры для линий, уровней и энергий ионизации, но не документированный общий REST/JSON API. Автоматизация ASD должна называться адаптером веб-интерфейса, а не официальным REST API.
- Chemistry WebBook принимает веб-запросы по имени, формуле, CAS и другим идентификаторам; формат зависит от конкретной формы и набора данных.
- Документированные REST API NIST существуют у отдельных продуктов, например NVD, но они не относятся к атомной спектроскопии.

При добавлении NIST-команд необходимо отдельно документировать базу, поля формы/CGI, единицы, формат результата и дату доступа.

## 6. Сохранение результатов

Научная команда создаёт неизменяемый каталог:

```text
/var/science-assistant/data/YYYYMMDDTHHMMSSZ-<dataset>-<uuid8>/
```

В нём находятся данные и `manifest.json` с источником, точными параметрами, временем, размером, числом строк и SHA-256. Форматы таблиц: ECSV, FITS, CSV и Parquet. Для сохранения единиц, масок и метаданных предпочтительны ECSV или FITS.

## 7. Двунаправленный поток через MCP Proxy

### 7.1 Клиент → сервер

1. Вычислить размер и SHA-256 исходного файла.
2. `data_upload_begin(relative_path, size_bytes, sha256, chunk_size, overwrite)`.
3. Читать локальный файл и вызывать `data_upload_chunk(transfer_id, offset, data_base64)`.
4. Продолжать только с offset, подтверждённого сервером.
5. `data_upload_complete(transfer_id)`.
6. Сравнить итоговые размер и SHA-256.

`data_upload_status` возвращает авторитетный offset после тайм-аута или перезапуска клиента.

### 7.2 Сервер → клиент

1. `data_download_begin(relative_path, chunk_size)`.
2. `data_download_chunk(transfer_id, offset, limit)`.
3. Декодировать `data_base64`, записать во временный файл и продолжить с `next_offset`.
4. Остановиться при `eof=true`.
5. Проверить размер и SHA-256, затем атомарно переименовать временный файл.

Повторный запрос с тем же явным offset безопасен. Размер raw-чанка по умолчанию 256 КиБ, максимум 768 КиБ; Base64 увеличивает JSON примерно на треть.


## 8. Временное файловое хранилище MCP

До передачи в сервер документации файлы принимаются без отдельной базы данных. Завершённые файлы находятся в `/var/science-assistant/data/files` с физическим именем `<file_id UUID4>-<исходное имя>`. Метаданные хранятся в JSON sidecar и позже могут быть переданы `doc-store-client`.

### 8.1 `file_receive`

Первая порция не содержит `upload_session_id`, имеет `part_index=0` и обязательно передаёт заголовок: `filename`, `part_count`, декодированный `size_bytes`, SHA-256 декодированного файла и `ttl_seconds`. Ответ содержит временный `upload_session_id` UUID4, но не содержит `file_id`.

Каждая следующая порция передаёт `upload_session_id`, `part_index` и фрагмент `data_base64_part`. Это фрагменты единой Base64-строки файла; отдельная порция не обязана декодироваться самостоятельно. Каждая успешно принятая порция продлевает TTL сессии. Просроченная сессия и её временные части удаляются.

Ответ на последнюю недостающую порцию формируется только после объединения Base64-фрагментов, декодирования во временный файл, проверки размера и SHA-256 и атомарного перемещения. Только этот ответ содержит постоянный `file_id` UUID4.

### 8.2 `file_get`

`file_get(file_id, part_index, part_size_bytes)` выдаёт файл по постоянному идентификатору частями. Ответ содержит `data_base64`, `part_count`, `offset`, `bytes_returned`, `eof`, исходное имя, общий размер и SHA-256.

### 8.3 `file_ls`

Пагинация обязательна: каждый вызов передаёт `page` и `page_size`. Ответ всегда содержит `total_items`, `total_pages`, `has_more` и `next_page`. `name_pattern` использует регистрозависимый shell glob, совместимый с привычными шаблонами `ls`: `*.pdf`, `report-??.csv`, `theta*`, `[0-9]*`.

## 9. Агентный пакетный транспорт

Полноценный `science-assistant-client` остаётся обычным Python-пакетом: он содержит импортируемую библиотеку и CLI-обёртку. Для среды модели отдельно выпускается `mcp_file_parts.py`. Этот скрипт использует только стандартную библиотеку Python, не открывает сетевых соединений и не импортирует инструмент модели. Он формирует параметры команд, а вызов `MCP_proxy.call_server` выполняет сама модель.

Поток агент → сервер:

1. `mcp_file_parts.py prepare` вычисляет размер, SHA-256, число частей и создаёт неизменяемый manifest.
2. `mcp_file_parts.py wait-payload` формирует параметры `data_package_wait`; команду рекомендуется сразу отправить с `use_queue=true`.
3. `mcp_file_parts.py part-payload` выдаёт параметры очередной `data_package_part`. Каждая часть имеет нулевой индекс, точный размер и собственный SHA-256.
4. Части разрешено передавать в любом порядке. Повтор идентичной части идемпотентен; часть с тем же индексом и другими байтами отклоняется.
5. `data_package_wait` дожидается полного набора, повторно проверяет каждую часть, собирает временный файл, проверяет общий размер и SHA-256, выполняет `fsync` и атомарный `os.replace`.
6. `data_package_status` возвращает общие счётчики и пагинированные массивы принятых/отсутствующих индексов.

Неизменяемые поля пакета: `package_id`, `relative_path`, `part_count`, `part_size_bytes`, `total_size_bytes`, `sha256`, `overwrite`. Один `package_id` нельзя повторно использовать с другим manifest.

Поток сервер → агент: `download-begin-payload` формирует `data_download_begin`, `init-download` создаёт локальный manifest из ответа, `download-part-payload` формирует каждый `data_download_chunk`, `accept-part` сохраняет ответ по индексу, а `assemble` ждёт все локальные части и принимает файл только после проверки размера и SHA-256.

## 10. Пакет клиента

Пакет `science-assistant-client` содержит импортируемую библиотеку и CLI-обёртку и является высокоуровневой оболочкой над `mcp_proxy_adapter.client.jsonrpc_client.JsonRpcClient`. Он не реализует собственный JSON-RPC или TLS-транспорт.

Основные методы:

- `ensure_compatible()`;
- `info()` и `iter_info_pages()`;
- `query_catalog()`, `query_object()`, `query_adql()`;
- `fetch_url()`;
- `upload_file()` и `download_file()` с resume и SHA-256;
- общий `call()` для новых команд.

Архив клиента включает wheel самого клиента, совместимый wheel `mcp-proxy-adapter`, README, примеры и тесты. Его можно распаковать и установить офлайн.

Для изолированных сред выпускается отдельный архив `science-assistant-client-py313-linux-x86_64-<version>.zip`. Скрипт `create_venv.sh` создаёт постоянный venv, по умолчанию `/mnt/data/science-assistant-client-venv`, и устанавливает все зависимости из Python 3.13 wheelhouse без сети. Прямой клиентский транспорт требует доступного сетевого маршрута к MCP Proxy; если агентная платформа предоставляет `call_server` только как инструмент модели, этот инструмент нельзя импортировать из обычного Python-процесса.

## 11. Метаданные команд

Каждая прикладная команда обязана публиковать:

- `name`, `version`, `description`, `category`, `author`, `email`;
- строгую JSON Schema без неизвестных полей;
- подробное описание;
- описание каждого параметра;
- структуру успешного результата;
- стабильные ошибки и способы восстановления;
- рабочие примеры;
- рекомендации;
- `query_format` для команд, принимающих поисковый язык или идентификаторы внешнего каталога;
- `pagination` для длинного вывода.

Точную схему одной команды следует получать через `help(cmdname="...")`.

## 12. Очередь

Короткие операции вызываются синхронно. Большие каталоги, ADQL и загрузки URL можно отправлять через `call_server(use_queue=true)`. Клиент скрывает опрос статуса и возвращает терминальный результат либо исключение.

## 13. Воспроизводимость

Для публикационного набора сохраняются:

1. каталог данных;
2. `manifest.json`;
3. точный идентификатор каталога, endpoint и запрос;
4. единицы и формат;
5. SHA-256;
6. версия клиента и сервера;
7. дата доступа к внешнему источнику.
